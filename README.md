# Контраст

Интерактивное визуальное эссе о том, как мы замечаем различия и как окружение меняет их смысл. Читатель следит за точкой и квадратом, слушает два окончания одной мелодии и встречает тритона, который приносит с собой другой мир.

**Автор — Алексей Гудков. Куратор — Олег Пащенко. Группа «Соевые кодеры», 2026.**

[Открыть эссе](https://pentaoo.github.io/contrast/) · [История разработки](https://github.com/pentaoo/contrast/commits/main/) · [Pull request проекта](https://github.com/pentaoo/contrast/pulls?q=is%3Apr)

## Как в проекте использовался ИИ

ИИ участвовал в обсуждении замысла, написании и переработке кода, редактуре текста, создании иллюстраций и проверках. Проект складывался постепенно: автор задавал направление, смотрел результат в браузере, уточнял поведение сцен и возвращал реализацию на доработку.

Основной способ работы — последовательные задания на конкретные изменения. Сначала нужно было собрать сцену, затем сделать движение понятнее, изменить переход, подобрать темп чтения, исправить звук или согласовать типографику. Из таких итераций получилась общая история с повторяющимися героями.

Этот README объединяет описание процесса и сведения о запуске проекта. Примеры ниже опираются на исходники, историю коммитов, описания pull request и материалы постановки сцен.

## От замысла к работающим сценам

Тема контраста требовала ситуаций, в которых различие можно пережить. Поэтому в процессе разработки обсуждались отдельные эпизоды, их порядок и связь с общим выводом. Рабочие идеи и сценарии фиксировались в заметках, чтобы переносить задачу между этапами разработки и ассистентами.

В итоговом маршруте осталось несколько связанных частей:

1. Обложка и пролог «Родилась она»: постепенное появление различий и переход к полю точек.
2. История фигур: одна точка выделяется, вырывается из сетки, оказывается в опасности и получает помощь маленького квадрата.
3. Бал: те же герои танцуют над спектром звучащих нот; одна мелодия получает два разных окончания.
4. Тритон и море: рисованный персонаж появляется среди геометрии, а затем меняет окружение для всех героев.
5. Погружение, источники и вывод о связи контраста с контекстом.

ИИ помогал разворачивать эти эпизоды в последовательность действий. Автор определял, что должно произойти со зрителем: куда он посмотрит, в какой момент узнает персонажа, где задержится и какое различие заметит. Проверять это приходилось на движущейся странице: описание сцены само по себе ещё не показывало, читается ли она.

## Как ставились задачи ассистентам

Для сложных сцен использовались подробные задания: события, настроение, ограничения, способ управления и признаки готового результата. Например, в истории точки задавались тревожный тон, преследование и спасение, плоская геометрия, отсутствие лиц и реплик у фигур. Так сохранялась возможность самостоятельно прочитать их движения как поведение персонажей.

После первого варианта задания становились короче и точнее. Требовалось усилить попытку точки вырваться из сетки, дать больше времени на чтение вопроса после погони, продлить падение тритона или убрать задержку появления его следующей позы.

Примеры задач в сокращённом пересказе:

- Построить сцену, где большой квадрат преследует точку, а маленький помогает ей уйти; сделать движение фигур понятным без поясняющих реплик.
- Сохранить мелодию, ритм и тембр в двух исполнениях, изменив одну ноту последнего созвучия.
- После окончания музыки уронить тритона на клавиатуру и связать момент удара со звуком.
- Сделать переход к морю так, чтобы тритон оказался в привычной среде, а геометрические герои — в чужой.
- Привести текст к общим типографическим ролям и убрать частные настройки, накопившиеся в сценах.

Это пересказ рабочих заданий. Он показывает степень конкретности, с которой автор направлял реализацию.

## Код, анимация и прокрутка

Ассистенты писали HTML, CSS и JavaScript, разделяли поведение по модулям и меняли уже работающие части по замечаниям автора. Для геометрии используются SVG и программно вычисляемые координаты; для графика звука — Canvas. Файлы в `dist/` являются редактируемыми исходниками сайта.

Одним из главных вопросов стало управление временем. За время разработки пробовались автоматическое проигрывание истории, блокировка прокрутки, закреплённые экраны и управление кадром от положения страницы. В текущей истории фигур прокрутка определяет кадр: движение вперёд и назад возвращает сцену в соответствующее состояние. Музыка запускается при достижении нужного места и затем играет в обычном темпе.

Такое разделение появилось в ходе нескольких правок. Читателю нужно свободно двигаться по визуальному рассказу, а музыкальной фразе — сохранять ритм. Ассистенты меняли расчёт прогресса, очереди нот, переходы между состояниями и сброс сцены при возвращении назад.

Проверяемые части логики вынесены в функции: вычисление кадра, продвижение музыкального времени, выбор событий и положение источников. Это позволило проверять повторяемость поведения и граничные состояния отдельно от браузерной отрисовки.

## Музыка и спектр

Музыкальная часть также создавалась через работу с кодом. Ноты, длительности и аккомпанемент описаны в JavaScript; звучание синтезируется в браузере средствами Web Audio API. Подсветка клавиш и движение героев связаны с исполняемыми нотами.

В первом окончании звучат до и ре-бемоль, во втором — два до через октаву. Предыдущие ноты, ритм и параметры событий совпадают. После второго исполнения появляется отдельное созвучие до–фа-диез, связанное с падением тритона и его именем.

ИИ помогал реализовать клавиатуру, планирование звуков, остановку исполнения, измерение спектра и синхронизацию изображения со звуком. Спектр строится из данных анализаторов Web Audio. Цвета графика соотносятся с подсвеченными клавишами и фигурами на балу.

Отдельной задачей была точность объяснения. При редактуре текста различили акустические свойства созвучия, слияние нот, приятность и ощущение завершённости. Поведение героев осталось художественной постановкой. Оно помогает рассказать историю, а впечатление от звучания читатель получает сам.

## Генерация тритона и моря

Рисунки тритона и моря создавались в ChatGPT по заданиям автора. Для персонажа использовался визуальный референс: человеческий торс, рыбьий хвост, раковина и фактура старой цветной иллюстрации. Эти свойства связывают его позы между собой и выделяют на фоне геометрического мира.

Для падения были подготовлены три состояния: полёт, удар и положение после удара. Каждому состоянию соответствовала пара изображений A/B. Затем появились дополнительные кадры зова раковины. Пары кадров дают эффект бумажной перекладки: голова, руки и хвост меняют положение заметными шагами.

В заданиях на изображения фиксировались:

- внешность, палитра и фактура одного персонажа во всех позах;
- прозрачный фон, целый силуэт и запас по краям;
- устойчивый масштаб торса и положение опоры внутри пары;
- достаточно крупные изменения частей тела, заметные после уменьшения;
- отдельная от персонажа геометрия пианино и окружающей сцены.

Сначала выбирался кадр A, затем на его основе готовился B. Эта последовательность помогала сохранять сходство персонажа. Изображения требовали отбора и совмещения: даже подходящий отдельный рисунок мог плохо переключаться с соседней позой.

В сайт встроены WebP с прозрачностью; исходные PNG и референс сохранены в `references/`. Переход на WebP и фоновая загрузка кадров стали отдельной технической доработкой. Автор заметил задержку при появлении трубящего тритона, после чего загрузку изображений перенесли на более ранний момент.

## Текст и оформление

ИИ участвовал в редактуре реплик, переходов и объяснений. Правки затрагивали длину фраз, профессиональные термины, связь между увиденным действием и последующим абзацем. В истории есть отдельный pull request с согласованными автором заменами строк.

Для пролога и музыкального объяснения потребовалась более содержательная редактура: уточнение статуса психоаналитической модели, связь текста с конкретными действиями фигур и разграничение утверждений о звуке. В финале был сформулирован прямой вывод: контраст позволяет заметить различие, а контекст меняет его значение.

Ассистенты также помогали упорядочивать оформление. Накопившиеся варианты размеров и начертаний свели к общим ролям: обложка, заголовок, лид, авторский голос, основной текст, подпись и кнопка. Для основного текста, подписей и интерфейса используется Manrope, для названия на обложке — Oswald, для курсивных акцентов — Georgia. Элементы собраны на [странице UI-kit](dist/ui-kit.html).

## Проверки и обратная связь

Работа с ИИ включала проверку предложенных изменений. В репозитории есть автоматические тесты логики, а в описаниях pull request зафиксированы браузерные прогоны на широком и узком экране, с уменьшением движения и без JavaScript. Автор просматривал результат и давал следующие задания по поведению страницы.

Автоматические проверки покрывают, в частности:

- повторяемость кадра при одинаковом прогрессе и корректность координат;
- отсутствие проникновения геометрических фигур друг в друга;
- порядок состояний пролога, погони, падения и морской сцены;
- совпадение двух музыкальных исполнений до последней изменённой ноты;
- постановку каждой ноты в очередь один раз и завершение звучания;
- движение ссылок на источники вперёд и назад;
- упрощённое поведение отдельных сцен при уменьшении движения.

На момент обновления README проходят 37 тестов. Синтаксис JavaScript проверяется отдельной командой. Зрительное восприятие, темп чтения, удобство прокрутки и впечатление от музыки дополнительно оцениваются при просмотре и прослушивании сайта.

Принятие результата оставалось частью авторской работы. Например, вариант со сливом на морском дне был добавлен, затем отменён; в следующей редакции герои погружались в темноту. История таких изменений сохраняет выбор между вариантами и показывает, как уточнялся замысел.

## Локальный запуск

Нужны Node.js и Python 3. В GitHub Actions используется Node.js 22. Команды выполняются из корня репозитория; в локальной папке проекта это каталог `site/`.

```sh
npm run dev
```

Сайт доступен по адресу [localhost:4173](http://localhost:4173). `dist/` сразу содержит исходники, которые отдаёт локальный сервер. Установка пакетов и отдельная сборка для запуска не требуются.

Проверки:

```sh
npm run check
npm test
```

Для проверки взаимодействий в браузере нужно пройти историю вперёд и назад, прослушать оба окончания, дождаться падения тритона, перейти к морю и источникам, затем воспользоваться кнопкой «Прочитать заново». Звук разрешается первым действием на странице; при необходимости появляется кнопка «Включить звук».

## Публикация и материалы

После обновления `main` workflow **Deploy GitHub Pages** проверяет синтаксис, запускает тесты и публикует содержимое `dist/`. Настройка источника GitHub Pages — GitHub Actions.

Научные источники, на которые опирается эссе, перечислены в самой статье. Рисунки тритона и моря созданы с использованием генеративного ИИ по заданиям автора. Manrope и Oswald распространяются по SIL Open Font License; тексты лицензий находятся рядом с файлами шрифтов в `dist/assets/`.
